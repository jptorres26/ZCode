# @zcode/node-repl-host

The shared host for `node_repl`: the JS execution surface (only one tool, `js`) and the two domain bridges (Browser Use, Computer Use) live here.

## Why it is a separate package

The host is **shared by official capabilities** and does not belong to any single plugin. It used to live inside `browser-use-plugin`, with these consequences:

- changing Computer Use required touching the browser-use package;
- the CUA SDK and docs each had a hand-maintained copy inside browser-use;
- `resolveBuiltInNodeReplMcpServers` only looked for the host build under browser-use's rootPath, so if the browser-use package was missing, CUA could not get the host even when enabled on its own.

The registration side was already centralized in the CLI core (`bootstrap/src/app/built-in-node-repl.ts`, keyed on "bua or cua enabled"); what was missing was **ownership of the build output**. This package moves the source to where it belongs.

## Build output is still carried by the plugin package

`dist/mcp/server.js` and `scripts/computer-use-client.mjs` are in the SEA release manifest (`OFFICIAL_BROWSER_USE_REQUIRED_SEED_PATHS`), so their paths cannot move. Therefore the browser-use build bundles from this package's `src/server.ts`, and the CUA client/docs copies are generated by the build script rather than maintained by hand. Moving the outputs out of the plugin root as well would require changing both the SEA manifest and bootstrap's hostPackage resolution, and is a separate step.
